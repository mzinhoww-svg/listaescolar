## Achados registrados durante o E2E (corrigidos antes de fechar a task)

- `features/webhooks/schemas.ts`: `SaveEndpointInputSchema` usava `z.url({ hostname: z.regexes.domain })`, que
  rejeita qualquer host literal (inclusive `127.0.0.1`) — travava a criação de endpoint mesmo em `APP_ENV=local`,
  porque a validação de FORMA (Zod) já aplicava uma política mais estrita que a de segurança de verdade (banco +
  `lib/net/safe-fetch.ts`). Corrigido para validar só "é uma URL http/https plausível"; a política fina continua
  só no banco (CHECK) e no `safe-fetch` (revalidado a cada envio).
- `app/b2b/webhooks/EndpointForm.tsx`: criar um endpoint chamava `onSaved()` imediatamente, que desmontava o
  próprio formulário (via `EndpointsSection` trocando `showNew` para `false`) ANTES de o dono ver o segredo —
  quebrava o "copie agora". Corrigido: o segredo fica visível até um "Já copiei" explícito, só então `onSaved()`
  roda (mesmo padrão dos diálogos de chave da S24, aqui inline em vez de `<dialog>`).
- Mesmo componente: "Revelar" e "Rotacionar" eram mutuamente exclusivos (revelar escondia o botão de rotacionar,
  e vice-versa) — um dono que revelasse o segredo não conseguia mais rotacioná-lo sem antes "Ocultar". Corrigido
  para os dois ficarem sempre acessíveis juntos, com "Rotacionar" pedindo uma confirmação inline (sem
  `window.confirm`, que trava a automação de teste — trocado por um segundo clique "Confirmar rotação").
