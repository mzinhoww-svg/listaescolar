# E2E · S17 LGPD e dados demonstrativos

Build de produção local (`pnpm build && PORT=3002 pnpm start`), worktree `T2-pipeline`, banco local
(`supabase_db_listacerta-t2`), roteiro `scripts/e2e-s17.sh` (agent-browser). Sessões `t2s17-<run>-p` (parent do
seed padrão, `parent@listacerta.test` — nunca excluída) e `t2s17-<run>-n` (e-mail novo e descartável, único
cenário que de fato exclui a conta). Fixture: um `consents` (`purpose='list_upload'`) inserido por SQL direto
para o `parent` antes do roteiro, para o cenário de revogação ter algo para revogar.

**Resultado: 18 PASS, 0 FAIL** (rodado após rebuild com os textos finais de `features/site/legal.ts`; a primeira
rodada, antes do rebuild, teve 2 falhas de texto porque o servidor ainda servia o build anterior às edições do
`legal.ts`, e 1 falha de aspas escapadas no próprio script de teste ao ler o JSON da exportação — corrigidas
antes desta rodada, sem mudança de produto).

## Cenários

1. Login (`parent@listacerta.test`, link mágico via Mailpit) → `/conta` mostra o link "Privacidade e dados".
2. `/conta/privacidade`: seções "Seus consentimentos" (com o consentimento fixture listado), "Exportar seus
   dados" e "Excluir sua conta" presentes.
   - Revogar o consentimento fixture: `revoked_at` aparece na tela e é gravado no banco.
   - Exportação (`fetch('/api/conta/exportar')`): JSON contém o próprio perfil (`id` do parent) e nunca um id de
     outro perfil.
   - Exclusão com confirmação errada ("sim" em vez de "excluir"): mensagem de erro, ninguém é apagado
     (`parent@listacerta.test` continua em `profiles`).
3. `/privacidade` (pública): aviso "Versão preliminar" presente; razão social ainda `[a definir: ...]` (aguarda
   humano/jurídico); o parágrafo de prazo de retenção já cita a exclusão de conta e NÃO é mais placeholder
   (preenchido pela S17 com o texto técnico provisório, sem número com unidade — ver Ruling do ledger sobre não
   inventar prazo).
4. Exclusão de conta de verdade, com e-mail novo (`s17-e2e-<run>@teste.invalid`, nunca usado antes): login cria a
   conta; confirmação correta ("excluir") apaga de verdade — `auth.users`/`profiles` do e-mail novo somem — e a
   sessão sai, voltando para `/entrar`.
