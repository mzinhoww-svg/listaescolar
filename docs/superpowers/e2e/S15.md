## Achados do roteiro (não são bugs do produto)

- **`clicktext` por `.click()` via `eval` falhou silenciosamente para o botão "Salvar aluno".** Um clique sintético
  (`elemento.click()`) não disparou a submissão do formulário nesta fatia, mesmo com o elemento certo encontrado.
  Corrigido usando `agent-browser find text "..." click` (clique real do Playwright) em vez de `.click()` via
  `eval` — consolidado como ajuste do padrão `clicktext` desta sessão (candidato a atualizar
  `01 - Padrões/PAT-002` no Segundo Cérebro).
- **`/carrinho/novo?lista=` espera o id da VERSÃO publicada (`list_versions.id`), não o id de `school_lists`.**
  `list_reader_get` (0601/S11) compara `p_list_id` com `list_versions.id` no caminho "oficial". Isso também revelou
  que a UI pública de uma lista oficial (`/escolas/[inep]/[serie]`) **não tem, hoje, nenhum link para "montar
  carrinho"** — só a cópia do pai (`ParentCopyEditor`) linka para `/carrinho/novo?lista=`. Registrado como dívida
  nova (ver `DEBT.md`).
- **React 19 reinicializa campos NÃO controlados de um `<form action={...}>` depois de QUALQUER conclusão da
  action, inclusive quando ela devolve erro** (não só em sucesso). O formulário de aluno (`StudentForm`) usava
  `defaultValue` para apelido, série e ano letivo — após a primeira tentativa recusada (apelido com espaço), esses
  campos voltavam ao estado inicial (vazio), fazendo a correção "aparente" (o campo mostrava o valor certo na tela)
  mas o `FormData` da segunda submissão continha os valores ANTIGOS/vazios de série e consentimento, causando falha
  silenciosa (bloqueio nativo de campo `required` vazio, sem mensagem visível). Corrigido tornando
  `nickname`/`gradeSlug`/`schoolYear`/`consent` CONTROLADOS (React state) em `StudentForm.tsx`,
  `GradeSelect.tsx` e `SchoolYearSelect.tsx` — campo controlado é imune ao reset nativo do `<form>`. Isto é uma
  correção de produto real (não só do roteiro): sem ela, QUALQUER usuário que errasse o apelido uma vez teria que
  reescolher a série e remarcar o consentimento, ou a segunda tentativa falharia silenciosamente.
- Uma navegação para `/conta` logo após criar o carrinho mostrou, uma única vez ao longo de várias repetições, um
  instantâneo desatualizado ("Nenhum carrinho ainda") na mesma sessão longa do agent-browser; uma nova sessão
  limpa mostrou o dado certo de imediato, e uma segunda navegação na mesma sessão também corrigiu. Tratado como
  instabilidade da ferramenta de E2E (não do produto): o roteiro reabre a página uma vez se o texto não aparecer
  em 8 s.
