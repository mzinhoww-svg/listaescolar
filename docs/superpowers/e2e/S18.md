# E2E · S18 Estados e acessibilidade

Build de produção local (`pnpm build && PORT=3003 pnpm start`), worktree `T3-comercio`, banco local
(`supabase_db_listacerta-t3`), roteiro `scripts/e2e-s18.sh` (agent-browser), reaproveitando
`scripts/e2e-lib.sh` (D-091, extraído nesta fatia). Sessões `t3s18-<run>-admin`/`-visit`. Fixture: uma escola,
lista publicada com 4 itens (2 em "Papelaria", 1 em "Higiene", 1 sem categoria) e uma denúncia `open` sobre essa
lista, inseridos por SQL direto antes do roteiro.

**Resultado final: 18 PASS, 0 FAIL.**

Uma rodada intermediária teve 1 falha real de ROTEIRO (não de produto), corrigida antes da rodada final: o passo
3 reabria a MESMA URL (`ab admin open` duas vezes para `/admin/denuncias/[id]`) esperando ver o `<select>` de
resolução habilitado depois de mudar o status para `reviewing` — mas reabrir a URL idêntica é um no-op (o
navegador/roteador não refaz a navegação), então a releitura via `eval` ainda via o DOM de antes do clique. A
falha foi confirmada como só de roteiro checando direto no banco (`select status from reports` já mostrava
`reviewing`) e com uma sessão nova, isolada, confirmando `disabled === false` logo após um login/abertura
genuína da mesma página. Corrigido trocando a releitura por `location.reload()` (força um GET de verdade) em vez
de reabrir a mesma URL — candidato a lição para o PAT-002 do Segundo Cérebro (mesma classe de achado de
"wait_text"/checkbox de sessões anteriores: reabrir a MESMA URL não é reload).

## Cenários

1. **D-034 + D-140 (lista oficial pública, `/escolas/[inep]/[serie]`)**: itens agrupados por categoria
   ("Papelaria", "Higiene", "Outros itens" por último, para o item sem categoria); link "Montar carrinho com
   esta lista" presente e apontando para `/carrinho/novo?lista=<id da versão publicada>` (não o id da lista).
2. **Foco visível/skip-link por teclado (`AdminShell`, novo nesta fatia)**: primeiro elemento focável ao entrar
   em `/admin` é o skip-link ("Pular para o conteúdo"), com `href="#conteudo"`; `main#conteudo` existe na casca.
3. **D-153 (`/admin/denuncias/[id]`)**: com a denúncia `open`, o `<select name=resolution>` e o botão "Resolver"
   ficam desabilitados (só "Colocar em análise" é uma transição válida); depois do clique em "Colocar em
   análise" (status vira `reviewing`), os mesmos campos ficam habilitados.
4. **Verificador axe-core** (via CDN `cdnjs.cloudflare.com/ajax/libs/axe-core`, sem dependência nova no
   projeto) em 3 rotas representativas: a lista pública, o dashboard do admin e o detalhe de uma denúncia —
   nenhuma violação de impacto `serious`/`critical` em nenhuma das três.
