# S26 · Campanhas de marca, insights e faturamento B2B · Plano de implementação (trilha B2B, faixa 05xx)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Parceiros do tipo **marca** (e EdTech, mesmo `partner_type`) criam **campanhas de sugestão de produto** cobradas por **CPM ou CPC** (bid declarado pelo próprio parceiro — nunca um preço inventado pela plataforma), sempre exibidas como **"Patrocinado"** e **nunca substituindo** um item cuja marca/especificação é exigida pela escola (alerta `restrictive_brand_or_spec` da lista, Lei 12.886/Procon) — bloqueio decidido **no banco**, na função que serve a campanha, não só na tela. Toda campanha passa por **aprovação do admin** (Admin16) antes de servir. **Insights agregados** (B2B08) mostram demanda por categoria × série × cidade com **k-anonimato** (padrão `min_k = 5`, configurável em banco): célula com menos de `min_k` listas distintas contribuindo fica oculta, e uma segunda célula é suprimida quando a supressão de uma única célula permitiria recuperar seu valor por subtração do total. **Faturamento B2B** (B2B09) gera um **extrato imutável** por período somando uso da API (S24) e acumulado de campanhas (bid × impressões/cliques, sempre um valor que o próprio parceiro declarou) — **sem cobrança automática**: o extrato é só um registro + instrução para o admin agir manualmente fora do sistema (nenhuma integração de pagamento nesta fatia). Impressão/clique contam sem cookie de terceiro e sem dado pessoal, com dedupe por chave anônima e limite por período para não inflar métrica.

**Aceite do PLAN:** teste de k-anonimato (célula oculta abaixo de `min_k`, supressão complementar) e teste de bloqueio Procon (campanha nunca serve, nem aparece elegível, para uma lista com item de marca exigida na categoria da campanha).

## Decisões de escopo (Rulings — ver `docs/superpowers/ledger-comercio.md`, seção "S26")

1. Bid/orçamento é **declarado pelo parceiro**, não um preço de tabela da plataforma — não fere "nunca inventar preço": é o próprio anunciante definindo quanto paga pelo próprio inventário.
2. Linha de "uso de API" no extrato fica **sempre `pricing_status = 'unavailable'`** nesta fatia (não existe tabela de preço da API B2B ainda, mesmo racional do `billing_unavailable` da S21/D-102): mostra contagem, não valor. Registrar como pendência humana (preço por request excedente) e dívida se necessário.
3. Enforcement do Procon é **uma função SQL única** (`b2b_campaign_serve`), fonte de verdade; a UI e o domínio só formatam o que ela devolve — nunca decidem elegibilidade em TypeScript.
4. k-anonimato: a agregação **crua** (contagem por célula) só existe numa função `SECURITY DEFINER` **`service_role`-only**; a supressão (k mínimo + complementar) é aplicada em TypeScript (`features/campaigns/insights-service.ts`), testada por unidade (rápido de cobrir combinações de fronteira).
5. Sem integração de pagamento real: `b2b_statements` é só um snapshot imutável (extrato) + `payment_instruction` (texto livre para o admin agir manualmente). Nenhuma Server Action debita saldo real nem chama gateway.
