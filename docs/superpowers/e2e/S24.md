## Achados e Rulings desta execução

- **Ruling (S24 T3):** `.env.local` local de E2E precisa também de `OPENROUTER_KEY`/`AI_MODEL_CHEAP`/`AI_MODEL_STRONG`
  (com valores fictícios, não usados pela S24) para `getServerEnv()` não lançar — sem eles, `features/b2b/wiring.ts`
  mascara qualquer erro de `getServerEnv()` como "pepper ausente" e a API `/v1` responde sempre `503`, mesmo com
  `B2B_API_KEY_PEPPER` correto. Achado durante a primeira tentativa de E2E (não é um bug do código da S24 — é uma
  variável de ambiente compartilhada por todo `lib/env.ts` que a fatia não tinha motivo para conhecer). Custo se
  não documentado: alto (quem tentar rodar a E2E da S24 isolada trava no mesmo 503 sem pista).
- **Ruling (S24 T3):** sessões do agent-browser usam o prefixo `t2s24-` (trilha 2), não `t5s24-` como o brief geral
  sugeria — mesma correção de trilha já registrada no Ruling S24 · Task 1 (a implementação roda em `T2-pipeline`).
- **Achado de script (corrigido antes do commit):** `agent-browser eval` devolve string como JSON (entre aspas);
  o helper `read_dialog_key` agora remove as aspas antes de comparar/usar a chave. Sem a correção, toda comparação
  com `lc_test_*`/`lc_live_*` falhava porque a string capturada começava com `"`.
- **Achado de script (corrigido antes do commit):** clique por texto (`clicktext`) escolhe o primeiro elemento em
  ordem do DOM; como o rótulo do rádio de decisão do admin e o texto do botão de confirmar são iguais
  ("Aprovar em sandbox", "Suspender"...), o clique por texto reclicava o rádio em vez de enviar o formulário. O
  roteiro agora usa `aside button[type=submit]` para a decisão do admin. Pelo mesmo motivo, revogar a chave
  **anterior** (não a mais nova) exige escopar o clique à linha da tabela que contém "Produção (anterior)" e, na
  confirmação, ao `<dialog open>` (o modal realmente aberto) — há um `<dialog>` de confirmação por chave no DOM o
  tempo todo, só um visível por vez.
