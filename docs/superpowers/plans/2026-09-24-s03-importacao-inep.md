# S03 · Importação INEP por CSV · Plano de implementação (trilha Dados, índice 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Tabelas `schools`, `import_batches`, `import_rows`; tela `/admin/importacoes` com upload de CSV do INEP processado no servidor em lotes (validação Zod das colunas, normalização, detecção de duplicidade, relatório de erros baixável, reprocessamento idempotente pelo hash do arquivo, atualização sem duplicar). Toda escola nasce `registered`.

**Architecture:** Regra de negócio pura em `features/schools/` (normalização, schema Zod das linhas, classificação de ação por linha, orquestração em lotes contra uma porta `SchoolsImportRepository`). Persistência atômica e rápida por função SQL `SECURITY DEFINER` (`import_apply_rows`) chamável só por `service_role`; o TypeScript fatia o CSV em lotes de 500 linhas e chama a função. Upload por Server Action (admin) → hash SHA-256 → lote. Download do relatório de erros por Route Handler admin-gated.

**Tech Stack:** Next.js 16, `csv-parse/sync`, `iconv-lite` (INEP costuma vir em latin1), Zod, Supabase (service role só no servidor), Vitest, agent-browser. Worktree em `../listaescolar-wt/T1-dados`, trilha 1 (`.track` = 1): `pnpm db:start`, `pnpm db:env`, app em `PORT=3001`.

**Spec:** `docs/SPEC.md` §4 (escola: dois eixos), §5 (Escolas, Importação), §8; `docs/PLAN.md` S03; `docs/decisions/ADR-004-trilhas-paralelas.md`. Telas de referência (desktop 1280×800): `docs/design/png|html/Admin02-Escolas` e `Admin03-EscolaDetalhe` (linguagem visual do admin; não há tela própria de importação → Ruling: a tela `/admin/importacoes` reutiliza componentes e layout do Admin02).

## Global Constraints
- Migration `supabase/migrations/0101_schools_and_imports.sql` (faixa Dados 01xx). Sem FK para tabelas de outras trilhas; FK para `municipalities` e `profiles` (existem em `main`) é permitida. Toda tabela: `id uuid primary key default gen_random_uuid()`, `created_at`, `updated_at` (trigger `set_updated_at`), RLS habilitada, auditoria por `audit_row_change` em `schools` (sem PII: contatos de escola são dado institucional público; ainda assim exclua `email`/`phone` do audit via argumentos do trigger).
- Enums novos: `school_network` (`federal`, `state`, `municipal`, `private`), `import_status` (`pending`, `processing`, `completed`, `failed`), `import_row_action` (`inserted`, `updated`, `duplicate`, `rejected`).
- `schools`: `inep text not null unique check (inep ~ '^[0-9]{8}$')`, `name`, `normalized_name`, `network school_network`, `neighborhood`, `address`, `cep`, `phone`, `email`, `municipality_id uuid not null references municipalities`, `verification_status verification_status not null default 'registered'`, `registry_source registry_source not null default 'inep_import'`, `source_batch_id uuid references import_batches`, `is_demo boolean not null default false`. Índice em `(municipality_id, normalized_name)`. **Cadastro INEP não é verificação:** import nunca muda `verification_status` de escola existente.
- `import_batches`: `file_name`, `file_hash text not null unique` (sha256 hex do arquivo bruto; base da idempotência), `source text`, `total_rows`, `inserted_count`, `updated_count`, `duplicate_count`, `rejected_count`, `status import_status`, `imported_by uuid references profiles`, `started_at`, `finished_at`, `is_demo boolean`. `import_rows`: `batch_id` FK, `row_number int`, `raw jsonb`, `normalized jsonb`, `errors jsonb` (lista de `{code, message}`), `action import_row_action`.
- RLS: `schools` — leitura pública (anon e authenticated) de escolas de municípios habilitados (`is_enabled`), admin/system leem todas; escrita só admin/system. `import_batches` e `import_rows` — só admin/system (select) e `service_role` (tudo). O papel do usuário vem de `profiles` via `auth_role()`.
- Colunas do CSV do INEP (Catálogo de Escolas): `CO_ENTIDADE` (INEP, 8 dígitos), `NO_ENTIDADE`, `CO_MUNICIPIO` (IBGE 7 dígitos), `NO_MUNICIPIO`, `SG_UF`, `TP_DEPENDENCIA` (1 federal, 2 estadual, 3 municipal, 4 privada), `DS_ENDERECO`, `NU_ENDERECO`, `NO_BAIRRO`, `CO_CEP`, `NU_DDD`, `NU_TELEFONE`, `DS_EMAIL` (opcional). Separador `;` ou `,` (detectar), codificação UTF-8 ou latin1 (detectar), cabeçalho obrigatório. Colunas obrigatórias: `CO_ENTIDADE`, `NO_ENTIDADE`, `CO_MUNICIPIO`, `TP_DEPENDENCIA`. Coluna obrigatória ausente → o arquivo inteiro falha com relatório (status `failed`, sem tocar em `schools`).
- Linhas de município **não habilitado** (`municipalities.is_enabled = false` ou inexistente) → ação `rejected` com erro `municipality_not_enabled` (habilitar o município e reprocessar é só dado). Nenhum município é habilitado pelo import.
- Ações por linha: `inserted` (INEP novo), `updated` (INEP existente com dados diferentes; atualiza nome/endereço/contatos/rede/`normalized_name`, nunca `verification_status`), `duplicate` (INEP repetido no mesmo arquivo, ou nome normalizado + município já existente com INEP diferente: não insere, registra), `rejected` (erro de validação Zod: INEP inválido, nome vazio, rede inválida, município não habilitado).
- Reprocessar o mesmo arquivo (mesmo hash) devolve o lote existente sem duplicar nada (`idempotent = true`). Arquivo novo com INEPs já existentes atualiza sem duplicar.
- A contagem de escolas exibida vem do banco (`select count(*)`) depois do processamento, nunca fixa no código. Dados demonstrativos: checkbox "Arquivo de demonstração" grava `is_demo = true` no lote e nas escolas; a UI mostra o selo "Demonstração".
- Server Action e Route Handler exigem admin (`requireAccess("/admin")`/checagem de papel via `profiles`, nunca por metadata). Limite de upload: 25 MB, tipos `text/csv`, `.csv`, `text/plain`. TypeScript strict, sem `any`, Zod em toda fronteira (form, CSV, saída da função SQL), componentes ≤250 linhas, `server-only` no que usa service role.
- Nenhum arquivo real do INEP no repositório: só o fixture de demonstração `tests/fixtures/inep-demo.csv` (escolas fictícias "Escola Demonstração N", INEPs fictícios de 8 dígitos, município de Cuiabá 5103403 e um município não habilitado) — nunca dado inventado apresentado como real.
- Ledger: Rulings desta trilha em `docs/superpowers/ledger-dados.md` (formato `Ruling: <decisão> — <motivo> — <custo se estiver errada>`).

## Review Focus
- Injeção/planos: CSV com célula começando por `=`, `+`, `-`, `@` (CSV injection) — o relatório de erros baixável precisa neutralizar (prefixar `'`); aspas, quebras de linha dentro de campo, BOM UTF-8, separador `;`, linha vazia no fim, colunas extras, colunas duplicadas, cabeçalho em caixa diferente.
- Idempotência sob concorrência: dois uploads simultâneos do mesmo arquivo não podem criar dois lotes nem duplicar escolas (constraint `unique(file_hash)` + tratamento do conflito).
- Falha no meio do processamento (lote 3 de 5 falha): estado consistente e retomável; lote fica `failed` com contadores parciais corretos ou a operação é atômica por lote de 500; reprocessar completa sem duplicar.
- Arquivo grande (ex.: 200 mil linhas): memória e tempo — processar em streaming/fatias, sem carregar tudo em `raw jsonb` gigante de uma vez; limite de tempo do Server Action (registre Ruling: se exceder, o processamento roda em segundo plano por Route Handler com `after()` e status consultável).
- Um não-admin (parent, school_member) não consegue chamar a Server Action nem baixar o relatório; `anon` não lê `import_*`.
- `updated_at` e auditoria corretos; `verification_status` nunca regride por reimport.
- Nome normalizado: acentos, caixa, pontuação, espaços múltiplos, abreviações comuns ("E.M.", "Esc.", "Prof.") tratadas de forma determinística e testada.
